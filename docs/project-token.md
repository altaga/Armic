# Project token ($ARMIC)

> The rehabilitation robot, safety stack, and edge agent are the **product**. **$ARMIC** is a **project-funding and launch layer** — it exists to make ARMIC real (hardware, kits, bench time, community). It is **not** a patient reward or clinical incentive mechanism.

## Why we launched it

People ask: *"Why onchain? Why a token? This is a rehab robot."*

| Layer | Role |
|-------|------|
| **Product** | UNO Q robot · edge agent · 5-layer safety · wearable · calibration SSoT |
| **$ARMIC** | Fund the build · ship kits · prove we can launch — **not** the therapy loop |

The token proves three things a GitHub repo alone cannot:

1. **We can launch** — liquidity, graduated fees, transparent routing to a **rehab hardware fund** (more UNO Q stations, arms, wearables for pilots).
2. **We can build audience** — [@projectarmic](https://x.com/projectarmic) and demo traction for clinic and partner conversations.
3. **We failed and learned** — prior wallet compromise drove multisig and custody hardening before any treasury use.

## What it is not

- **Not** a rep-quality reward for patients completing therapy.
- **Not** a substitute for clinical evidence, IRB review, or regulated care.
- **Not** wired into the on-device adaptation loop (ROM widen/narrow runs on rep quality alone — see [agent.md](agent.md)).

Session telemetry (`rep_end`, WebSocket history) is for **measurement and care-team review**. Any future onchain session proofs would be **audit infrastructure**, not pay-for-reps.
